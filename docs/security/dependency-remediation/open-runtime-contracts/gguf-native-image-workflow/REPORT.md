# GGUF native-image workflow proposal — local verification

## Outcome

One new merge-target file only: `mirror/.github/workflows/gguf-native-image-qualification.yml`. No launcher/probe/test/doc/lock/CI-bootstrap changes. No publication, workflow dispatch, Docker engine access, registry request, pull, container, compiler, model, SDK, GPU or cloud execution.

The workflow has PR and `hermes/apple-silicon-audit` push triggers, plus optional manual dispatch. Checkout remains pinned to the supplied verified v6 revision, `contents: read`, `persist-credentials: false`, depth one, and only the two public source files. Event/context values enter through quoted environment data, never interpolated shell source.

The inline stdlib controller parses one unambiguous top-level `GGUF_IMAGE` string literal using AST; it never imports or executes the launcher. It uses that exact value for pull/run, refuses malformed/unpinned/wrong-repository/slim defaults before pull, and derives the expected JSON RepoDigest from the same value. This is internal qualification-default validation, not a change to explicit user-image semantics.

## Native/evidence boundary

The proposed real run checks actual host + GitHub runner + Docker server + image Linux/amd64 identity, records actual checkout SHA separately from event head/context SHA, source SHA-256 values, exact image input, engine version, image ID/platform/RepoDigests, command exits/raw logs and the full probe receipt. It invokes exactly `python -I -B -S /probe.py`, requires full-mode Linux/x86_64 Python 3.12 receipt, source-hash agreement and both expected C/C++ outputs. The parent-owned qualifier remains responsible for its exact uv-release validation; there is no native-only or banner-validation bypass.

Only an owned frozen copy of the public probe is mounted read-only. Docker client credentials are empty, endpoint fixed to the local Unix socket and client environment allowlisted. Runtime has no network, read-only root, UID/GID 65534, ALL capabilities dropped, no-new-privileges, CPU/memory/PID bounds and owned exec-enabled tmpfs. No host socket/workspace/credential mount, forwarded secret, GPU flag or install.

Primary failures remain nonzero even if cleanup also fails. An unambiguous no-follow call-owned CID plus ownership-label/ID readback is required before force-removal. Already-absent CID is benign only after successful full-ID Docker readback. An `rm` exit is never absence proof; unreachable daemon, malformed list, wrong ownership, missing/unsafe CID and still-present container remain nonqualification. All command logs and final receipt print as escaped JSON into CI logs on ordinary failure. Graceful signals get bounded cleanup; hard termination/runner loss cannot promise cleanup or a final absence receipt and this limitation is printed before execution.
