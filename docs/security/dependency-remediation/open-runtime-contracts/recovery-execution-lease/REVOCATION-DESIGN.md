# Pre-edit follow-up: retain cancellation bytes until child admission

The first complete checkpoint (113 passing tests) is retained. Reviewing the new shared-read descriptor exposed a cancellation-specific boundary not present for persistent EOF: the supervisor could consume K/T after forwarding E but before the child checks its duplicate, and pause before acting on that cancellation. The child would then see an empty, still-open stream. A deterministic RED is being added before changing production.

Use the existing CLOEXEC launch-status pipe as the reader-handoff boundary. Before real exec (or child exit) closes its writer, the supervisor must ONLY poll caller-channel readability, never consume a post-E byte. Any readability/error in this phase cancels anchored work. The child remains the only reader authorized to consume pending post-E cancellation at its last gate. Thus a supervisor hold cannot erase cancellation while the child has not yet admitted exec. After launch EOF proves real exec/exit crossed that boundary, the supervisor can consume the normal teardown stream. This introduces no new FD, runtime clock, protocol buffer, dependency or ownership mechanism.

At a concurrent cancellation after successful final child validation, execution was already admitted and the independent supervisor still owns revocation. The same scheduling/failure limits in DESIGN.md remain; this does not claim atomic POSIX pipe-check-plus-exec. Test hold: actual private E write is observed, K is then queued separately, the child is delayed only 50ms with its lease still valid, and an old supervisor that consumes K is held for 1300ms. The old path actually executes despite the consumed pre-admission cancellation; the repaired path must never erase K before the child gate and must clean up with no work and no fixture kill.
